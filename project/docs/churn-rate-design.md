# 離患率設計 README（契約タイプ別）

> **ステータス:** 設計確定・実装前  
> **表示予定:** アラートページ上部（サマリー）＋ 経営ルール設定（閾値・分類）  
> **関連コード（現状）:** `InactivePatientAlerts.tsx`, `BusinessRulesConfig.tsx`, `lib/businessRules.ts`, `lib/repeatMetrics.ts`

---

## 1. 目的

整体院の成約タイプ（都度 / プログラム / 回数券）ごとに **離患率を分けて見える化** し、

- 経営判断（プログラム設計・フォロー投資）
- 現場アクション（誰に連絡するか）

を同じデータから両方できるようにする。

**全体平均の離患率は出さない**（プログラム主体の院では誤解を生むため）。

---

## 2. 用語の整理（必ず分ける）

| 用語 | 英語イメージ | 意味 | 既存機能 |
|------|-------------|------|----------|
| **離脱** | At-risk | 「そろそろ連絡したい」運用アラート | アラートページ B1/B2/B3、`inactive_days_threshold`（既定30日） |
| **離患** | Churned | 成約起点で、一定期間内に継続来院が途絶えた状態 | **本 README で新規定義** |
| **離患率** | Churn rate | コホート内で離患した人の割合（％） | **本 README で新規実装** |

既存の `churn_lapsed_days`（既定90日）は「最終活動から何日空いたら離患扱いか」の **単一閾値**。  
本設計は **契約タイプ別・複数観察窓** のコホート指標として置き換え・拡張する（90日ルールはフォールバックとして残してもよい）。

---

## 3. 成約タイプ（3区分）

顧客は **成約時点の主契約** で1区分に分類する（後から都度に変わっても、成約コホートは固定）。

| ID | 名称 | 典型例 | 優先度 |
|----|------|--------|--------|
| `single` | ①単発都度 | 都度メニュー、単発施術 | 補助KPI |
| `program` | ②プログラム | 6M / 3M / 10-12M 等 | **主戦場** |
| `ticket` | ③回数券 | 回数券表記あり（`import_ticket_count_raw` 等） | ②と同窓で開始 |

### 3.1 自動分類ルール（実装案）

来院レコード・顧客履歴から **成約日（後述）の来院** を見て判定。優先順位は上から。

1. **プログラム** … 次のいずれかに該当  
   - `menu_name` / `import_kind_text` / `payment_detail` 名にプログラムキーワード（経営ルールで設定）  
   - 例: `6M`, `6ヶ月`, `3M`, `12M`, `10-12`, `プログラム`
2. **回数券** … プログラムでなく、回数券列に意味のある表記  
   - `import_ticket_count_raw` が空でない（かつプレースホルダーでない）
3. **都度** … 上記以外の有効来院成約

**分母から除外（既存と同じ）:**  
`exclude_keywords` に含まれるメニュー（既定: `BE`, `初回`, `体験` および `初`）のみの来院は、成約日・有効来院の判定に使わない。

### 3.2 プログラムのサブ区分（②のみ）

ダッシュボードでは **②をさらにプログラム長で内訳** する。

| サブID | 判定キーワード例 |
|--------|------------------|
| `prog_3m` | 3M, 3ヶ月 |
| `prog_6m` | 6M, 6ヶ月 |
| `prog_10_12m` | 10-12, 12M, 12ヶ月 |

該当なしは `prog_other` にまとめる。

## 4. 成約日（コホート起点）

| 項目 | 採用定義 |
|------|----------|
| **成約日** | その顧客の **最初の有効来院日**（`firstQualifyingVisitDate` — `lib/repeatMetrics.ts`） |
| **BEとの関係** | BE来院は `exclude_keywords` で除外済み。実務上は「本契約の初回来院」＝成約日 |
| **院スコープ** | 川西 / 高槻 / 全院 は集計フィルタで切替（既存 `clinicScope` と同様） |

---

## 5. 離患の定義

### 5.1 有効来院

`filterQualifyingVisits` を通過した来院（除外キーワード以外の `menu_name`）。

### 5.2 離患判定（窓ごと）

観察窓 `W`（例: 180日 = 6ヶ月）について:

1. 成約日を `T0` とする  
2. 観察終了日 `T_end = T0 + W`  
3. **今日 ≥ `T_end` の顧客だけ** を分母候補にする（観察未完了は率に入れない）  
4. 区間 `(T0, T_end]` に有効来院が **1回もない** → その窓で **離患**  
5. 区間内に1回でもあれば **継続**（その窓では非離患）

> 補足: 「半年以降の離患％」＝成約から6ヶ月以内に一度も来なかった人の割合、と読む。  
> 「最終来院から6ヶ月」ではない（コホート型のため）。

### 5.3 継続率

```
継続率(W) = 100% − 離患率(W)
```

UI では **離患率と継続率を並記**（現場は継続率の方が直感に合うことが多い）。

## 6. 観察窓（タイプ別）

### ① 単発都度 (`single`)

| 窓ID | 日数 | ラベル |
|------|------|--------|
| `w_3m` | 90 | 3ヶ月以内離患 |
| `w_6m` | 180 | 6ヶ月以内離患 |

都度はライフサイクルが短いため **3ヶ月＋6ヶ月の2段**（6ヶ月のみだと早期離脱が見えにくい）。

### ② プログラム (`program`)

| 窓ID | 日数 | ラベル |
|------|------|--------|
| `w_6m` | 180 | 6ヶ月 |
| `w_1y` | 365 | 1年 |
| `w_18m` | 548 | 1.5年 |
| `w_2y` | 730 | 2年 |

サブ区分（6M / 3M / 12M）ごとに **同じ窓** で率を出す。  
6Mプログラムの経営判断は **`w_6m` を最重要** として強調表示。

### ③ 回数券 (`ticket`)

初期実装は **②と同一窓**（`w_6m`, `w_1y`, `w_18m`, `w_2y`）。

将来拡張（Phase 2）:

- 券消化停滞（購入からX日で残回数がY%以上）
- 回数券離患とプログラム離患の定義分離

## 7. 離患率の計算式

```
離患率(W) = 離患人数(W) / 分母人数(W) × 100

分母人数(W) = 成約タイプが該当 かつ 今日 ≥ 成約日+W かつ プレースホルダー顧客(10000)除外
離患人数(W) = 分母のうち、区間 (成約日, 成約日+W] に有効来院が0回
```

表示は **小数1位**（既存リピート率と同じ `round(x*1000)/10`）。

**必ず `n=分母` を併記**（人数が少ないと％だけでは誤解される）。

## 8. UI 配置

### 8.1 アラートページ（`InactivePatientAlerts`）

```
┌─ 離患率サマリー（契約タイプ別）────────────────────┐
│ ①都度     3M: 42.0% (n=120)  6M: 58.3% (n=98)     │
│ ②プログラム                                          │
│   全体   6M: 18.0% (n=210)  1Y: 35.2% (n=156) …    │
│   6M契約 6M: 12.1% (n=85)                          │
│   12M契約 1Y: 28.4% (n=62)                         │
│ ③回数券   6M: …  1Y: …                             │
└────────────────────────────────────────────────────┘
  ↓ 既存: アラート・フォロー帯 / 誕生日 / 離脱予備軍リスト
```

- 各％をタップ → 該当コホートの **離患者リスト**（氏名・成約日・最終来院・LTV）  
- リストから個別フォローへつなぐ

### 8.2 経営ルール設定（`BusinessRulesConfig`）

赤丸から順に実装する想定:

| パネル | 内容 |
|--------|------|
| 離脱判定基準 | 既存（運用アラート日数）— 変更なし |
| **離患判定（分析）** | 本設計の閾値・キーワード・窓の ON/OFF |
| 稼働率以降 | 既存のまま |

追加する設定キー（`business_rules` テーブル案）:

| rule_key | 例 | 説明 |
|----------|-----|------|
| `churn_program_keywords` | `6M,6ヶ月,3M,12M,10-12` | プログラム判定 |
| `churn_ticket_required` | `true` | 回数券列必須判定 |
| `churn_windows_single` | `90,180` | 都度の観察日数 |
| `churn_windows_program` | `180,365,548,730` | プログラムの観察日数 |
| `churn_windows_ticket` | `180,365,548,730` | 回数券（初期は program と同じ） |
